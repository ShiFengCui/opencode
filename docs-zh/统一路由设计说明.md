# 统一路由设计说明

**文档目的**: 解释为什么需要统一路由层，以及它的核心价值

---

## 一、什么是统一路由？

### 1.1 当前问题

**没有统一路由时**:

```
客户端请求
    ↓
┌─────────────────────────────────┐
│  Flow 服务器                     │
│                                 │
│  /graph/start    → Graph 路由    │
│  /graph/status   → Graph 路由    │
│  /session/       → ❌ 不存在     │
│  /session/:id    → ❌ 不存在     │
│  /event          → ❌ 不存在     │
└─────────────────────────────────┘

问题：opencode 客户端无法连接 Flow 服务器
因为客户端期望的 API 端点不存在
```

### 1.2 统一路由方案

**有统一路由后**:

```
客户端请求
    ↓
┌─────────────────────────────────┐
│  统一路由层                      │
│  (ProtocolRoutes)               │
│                                 │
│  /session/*      → 协议适配器    │
│  /message/*      → 协议适配器    │
│  /event          → 协议适配器    │
│  /flow/*         → Flow 独有路由 │
└─────────────────────────────────┘
    ↓
┌─────────────────────────────────┐
│  协议适配器层                     │
│                                 │
│  OpenCode 会话 → OpenCodeAdapter│
│  Flow 会话     → FlowAdapter    │
└─────────────────────────────────┘
```

## 二、统一路由的核心作用

### 2.1 作用一：协议兼容

**问题**: OpenCode 客户端期望的 API 端点

```typescript
// opencode CLI 客户端代码
const client = createClient({
  baseUrl: 'http://localhost:4097', // Flow 服务器
})

// 客户端期望这些端点存在
await client.session.create()      // POST /session
await client.session.list()        // GET /session
await client.message.create(...)   // POST /session/:id/message
await client.event.subscribe()     // GET /event
```

**没有统一路由**:

```
POST /session  → 404 Not Found ❌
GET /session   → 404 Not Found ❌
GET /event     → 404 Not Found ❌

客户端无法工作！
```

**有统一路由**:

```typescript
// packages/flow/src/server/routes/protocol.ts

export function ProtocolRoutes() {
  const router = new Hono()

  // 实现客户端期望的所有端点
  router.post("/session", async (c) => {
    const input = await c.req.json()
    const adapter = protocolRouter.get("opencode")
    const session = await adapter.session.create(input)
    return c.json(session)
  })

  router.get("/session", async (c) => {
    const adapter = protocolRouter.get("opencode")
    const sessions = await adapter.session.list(c.req.query())
    return c.json(sessions)
  })

  router.get("/event", async (c) => {
    const adapter = protocolRouter.get("opencode")
    return streamSSE(c, async (stream) => {
      for await (const event of adapter.events.subscribe()) {
        await stream.writeSSE({ data: JSON.stringify(event) })
      }
    })
  })

  return router
}
```

```
POST /session  → 200 OK ✅
GET /session   → 200 OK ✅
GET /event     → 200 OK (SSE) ✅

客户端正常工作！
```

**价值**: **客户端无需修改，可直接连接 Flow 服务器**

### 2.2 作用二：自动引擎选择

**问题**: 如何根据会话类型选择执行引擎？

**统一路由解决方案**:

```typescript
router.post("/session/:id/message", async (c) => {
  const sessionID = c.req.param("sessionID")
  const input = await c.req.json()

  // 自动选择适配器
  const adapter = protocolRouter.select(sessionID)

  // 流式响应
  return streamSSE(c, async (stream) => {
    for await (const message of adapter.message.create(sessionID, input)) {
      await stream.writeSSE({
        data: JSON.stringify({
          type: "message.part.updated",
          properties: { message },
        }),
      })
    }
  })
})
```

**自动选择逻辑**:

```typescript
// ProtocolRouter.select()
select(sessionID: string): IProtocolAdapter {
  if (sessionID.startsWith('flow-')) {
    return this.get('flow')  // Flow 会话 → Flow 引擎
  }
  return this.get('opencode')  // 普通会话 → OpenCode 引擎
}
```

**使用示例**:

```typescript
// 创建普通会话（使用 OpenCode 引擎）
const session1 = await client.session.create({ title: 'Normal' })
// session1.id = "session_abc123"
await client.message.create(session1.id, { parts: [...] })
// → 自动使用 OpenCodeAdapter

// 创建 Flow 会话（使用 Flow 引擎）
const session2 = await client.session.create({
  title: 'Flow',
  agent: 'flow',
})
// session2.id = "flow_abc123"
await client.message.create(session2.id, { parts: [...] })
// → 自动使用 FlowAdapter
```

**价值**: **客户端无感知，自动选择正确的执行引擎**

### 2.3 作用三：统一中间件

**问题**: 认证、CORS、错误处理需要统一

**没有统一路由**:

```typescript
// Graph 路由 - 自己的错误处理
app.post('/graph/start', async (c) => {
  try {
    // ...
  } catch (err) {
    return c.json({ error: err.message }, 500)  // 格式 A
  }
})

// 其他路由 - 不同的错误处理
app.post('/other', async (c) => {
  try {
    // ...
  } catch (err) {
    return c.json({ message: err.message }, 500)  // 格式 B
  }
})

客户端需要处理不同的错误格式！
```

**有统一路由**:

```typescript
// 统一错误处理中间件
app.onError((err, c) => {
  if (err instanceof NamedError) {
    return c.json(err.toObject(), { status: 500 }) // 统一格式
  }
  return c.json({ error: err.message }, 500)
})

// 所有路由都使用统一的错误处理
app.route("/", ProtocolRoutes()) // ✅ 统一错误处理
app.route("/flow", FlowRoutes()) // ✅ 统一错误处理
```

**统一中间件**:

```typescript
export function createServer() {
  const app = new Hono()

  // 统一中间件
  app.use("*", corsMiddleware) // 统一 CORS
  app.use("*", authMiddleware) // 统一认证
  app.use("*", logMiddleware) // 统一日志
  app.use("*", errorMiddleware) // 统一错误处理

  // 统一路由
  app.route("/", ProtocolRoutes()) // 兼容 OpenCode
  app.route("/flow", FlowRoutes()) // Flow 独有

  return app
}
```

**价值**: **统一的认证、CORS、错误处理，客户端体验一致**

### 2.4 作用四：Flow 独有功能隔离

**问题**: Flow 的图执行功能如何暴露给客户端？

**统一路由方案**:

```typescript
export function createServer() {
  const app = new Hono()

  // 兼容 OpenCode 的路由（客户端无需修改）
  app.route("/", ProtocolRoutes())

  // Flow 独有路由（使用 /flow 前缀区分）
  app.route("/flow", FlowRoutes())

  return app
}
```

**Flow 独有功能**:

```typescript
// /flow/graph/start - 启动图执行
POST /flow/graph/start
{
  "graphID": "my-custom-graph",
  "nodes": [...],
  "edges": [...],
}

// /flow/graph/visualize - 可视化图
GET /flow/graph/:id/visualize

// /flow/node/register - 注册自定义节点
POST /flow/node/register
{
  "type": "my-custom-node",
  "code": "...",
}
```

**价值**: **兼容现有客户端的同时，支持 Flow 独有功能**

## 三、统一路由的价值总结

### 3.1 对客户端的价值

| 价值       | 说明               | 示例                       |
| ---------- | ------------------ | -------------------------- |
| **零修改** | 客户端代码无需修改 | opencode CLI 直接连接 Flow |
| **无感知** | 不感知底层引擎切换 | 自动选择 OpenCode/Flow     |
| **一致性** | 统一的 API 格式    | 错误、响应格式一致         |

### 3.2 对开发者的价值

| 价值         | 说明                   | 示例                |
| ------------ | ---------------------- | ------------------- |
| **代码复用** | 复用 OpenCode 路由代码 | 直接复制 session.ts |
| **易于维护** | 统一的路由结构         | 清晰的目录结构      |
| **易于扩展** | 轻松添加新功能         | /flow 前缀隔离      |

### 3.3 对架构的价值

| 价值       | 说明               | 示例                   |
| ---------- | ------------------ | ---------------------- |
| **解耦**   | 协议层与执行层解耦 | 可独立替换引擎         |
| **可扩展** | 支持多引擎并存     | OpenCode + Flow        |
| **可测试** | 独立测试各层       | 协议层测试、路由层测试 |

## 四、统一路由实现示例

### 4.1 完整的路由层

```typescript
// packages/flow/src/server/index.ts

export function createServer() {
  const app = new Hono()

  // ========== 统一中间件 ==========
  app.use("*", corsMiddleware) // 统一 CORS
  app.use("*", authMiddleware) // 统一认证
  app.use("*", logMiddleware) // 统一日志
  app.use("*", errorMiddleware) // 统一错误处理

  // ========== 统一路由 ==========
  // 兼容 OpenCode 客户端（核心协议）
  app.route("/", ProtocolRoutes())

  // Flow 独有功能（扩展功能）
  app.route("/flow", FlowRoutes())

  // 健康检查
  app.get("/health", (c) =>
    c.json({
      status: "ok",
      adapters: ["opencode", "flow"],
    }),
  )

  return app
}
```

### 4.2 ProtocolRoutes 实现

```typescript
// packages/flow/src/server/routes/protocol.ts

export function ProtocolRoutes() {
  const router = new Hono()

  // === 会话管理 ===
  router
    .get("/session", async (c) => {
      const adapter = protocolRouter.select(c.req.query("sessionID"))
      const sessions = await adapter.session.list(c.req.query())
      return c.json(sessions)
    })
    .post("/session", async (c) => {
      const adapter = protocolRouter.get("opencode")
      const session = await adapter.session.create(await c.req.json())
      return c.json(session)
    })

  // === 消息管理 ===
  router.post("/session/:id/message", async (c) => {
    const sessionID = c.req.param("id")
    const adapter = protocolRouter.select(sessionID)

    return streamSSE(c, async (stream) => {
      for await (const msg of adapter.message.create(sessionID, await c.req.json())) {
        await stream.writeSSE({ data: JSON.stringify(msg) })
      }
    })
  })

  // === 事件订阅 ===
  router.get("/event", async (c) => {
    const adapter = protocolRouter.select(c.req.query("sessionID"))

    return streamSSE(c, async (stream) => {
      await stream.writeSSE({ data: JSON.stringify({ type: "server.connected" }) })

      for await (const event of adapter.events.subscribe(c.req.query("sessionID"))) {
        await stream.writeSSE({ data: JSON.stringify(event) })
      }
    })
  })

  // === 权限管理 ===
  router
    .get("/permission", async (c) => {
      const adapter = protocolRouter.get("opencode")
      return c.json(await adapter.permission.list())
    })
    .post("/permission/:id/reply", async (c) => {
      const adapter = protocolRouter.get("opencode")
      await adapter.permission.reply(c.req.param("id"), await c.req.json())
      return c.json({ success: true })
    })

  // === 文件操作 ===
  router
    .get("/file", async (c) => {
      const adapter = protocolRouter.get("opencode")
      return c.text(await adapter.file.read(c.req.query("path")))
    })
    .post("/file", async (c) => {
      const adapter = protocolRouter.get("opencode")
      await adapter.file.write(c.req.query("path"), await c.req.json())
      return c.json({ success: true })
    })

  return router
}
```

## 五、没有统一路由会怎样？

### 5.1 客户端需要修改

```typescript
// ❌ 没有统一路由 - 客户端需要适配 Flow

// opencode CLI 需要修改
const client = createFlowClient({
  // 需要新的客户端
  baseUrl: "http://localhost:4097",
})

// 使用不同的 API
await client.graph.start() // 不是 session.create()
await client.graph.status() // 不是 session.list()
```

### 5.2 维护成本高

```
opencode CLI 团队需要:
1. 维护两套客户端代码（OpenCode + Flow）
2. 处理不同的 API 格式
3. 处理不同的错误格式
4. 处理不同的认证方式

Flow 团队需要:
1. 维护独立的文档
2. 支持两套客户端
3. 处理兼容性问题
```

### 5.3 用户体验差

```
用户需要:
1. 学习两套 API
2. 使用不同的客户端
3. 处理不同的配置
4. 面对不同的错误提示
```
